# weatherLab v1 為什麼不準,v2 怎麼改

> 2026-09-21 SS 決定收掉 v1(預測拿去買 Polymarket 天氣市場都買不中)。這份是 Claude 看過 v1 程式後寫的診斷與 v2 方向,給另一個對話實作用。
> 這是工具改善建議,不是投資建議;下注金額與要不要下注由 SS 自己決定。

## 一句話結論

v1 不是「模型不準」,是**在量錯的東西**:預測的地點、時段、資料來源都跟 Polymarket 的結算規則對不上。就算模型完全正確,也會系統性買錯格子。

## v1 的五個結構性問題(看程式確認過)

| # | 問題 | 在哪 | 影響 |
|---|---|---|---|
| 1 | **「一天」用 UTC 切** | `weather_forecast*.py` 的 `"timezone": "UTC"` | 東京的「日高溫」變成當地 09:00~隔天 09:00 的最高溫,紐約則是 20:00~隔天 20:00。市場結算用的是**當地日曆日**。這一條就足以讓答案整格偏掉 |
| 2 | **地點是市中心座標,不是結算測站** | 城市清單用市中心經緯度 | Polymarket 每個天氣市場都指定**某一個機場測站**,並以某個資料頁的數字結算(例如紐約常見是 LaGuardia、倫敦常見是 London City Airport——**以每個市場的 Rules 原文為準**)。市中心與機場差 1~3°C 很常見 |
| 3 | **「實際溫度」拿的是再分析格點,不是測站實測** | `update_actuals.py` 用 `archive-api.open-meteo.com` | archive 是 ERA5 類的 ~25km 格點重建值,會把高溫削平。拿它當答案,等於用另一個模型去驗模型,「準確率」本身就不可信 |
| 4 | **只有點預測,沒有機率** | 只存三個模型的單一高/低溫 | 市場賣的是「落在某一格(如 1°F 或 1°C 區間)」的機率。一個點預測沒辦法告訴你 P(這一格) 是 20% 還是 45%,就無從判斷市價便不便宜 |
| 5 | **單位與進位不一致** | `round()` 成整數 °C | 美國市場用 °F 整數格;先轉 °C 再四捨五入會掉進隔壁格。進位規則必須照結算資料源的顯示方式 |

另外:資料管線 2026-08-23 起因 Google Sheet OAuth token 過期一直寫入失敗,之後的數據等於沒收到。

## v2 做法(照順序,前一步沒過不要做下一步)

### 1. 對準結算規則(最重要,先做)
- 每個要追的市場建一筆設定:`market_slug / 測站 ICAO / 結算資料源網址 / 單位 °F或°C / 格子寬度 / 當地時區`。規則抄市場 Rules 原文,不要憑印象。
- 預測取**測站座標**,`timezone` 設成**測站當地時區**。
- 實際值取**結算資料源同一個測站**的觀測(METAR 或市場指定的頁面),照它的進位方式。

### 2. 從點預測改成機率
- 用 Open-Meteo **Ensemble API**(免費):ECMWF ENS 51 個成員 + GFS/GEFS 31 個成員,每個成員算一次當地日最高溫 → 直接數出落在每一格的比例 = P(格子)。
- **偏差校正**:每個測站用最近 30~60 天「預測 − 實測」的平均誤差把整個分布平移(簡單版 MOS)。機場站跟格點的系統偏差通常比模型之間的差異還大。

### 3. 記錄市價,做回測,先紙上交易
- 每次快照同時抓該市場各格的價格(Polymarket Gamma API 公開、免登入)。
- 對每格算 `edge = 我們的 P − 市價`。只有 edge 大於「手續費 + 價差 + 安全邊際」才記一筆**模擬單**。
- 跑滿至少 30 個結算日再看:我們的機率有沒有校準(Brier score / 分箱校準圖)、模擬單的累計結果。**沒有比市價更準,就不要用真錢。**

### 4. 真正可能有 edge 的地方:結算當天的即時觀測
- D-1 以前的預報大家都看得到,市價多半已經反映。
- 結算**當天**,每小時的 METAR 會告訴你「到目前為止的最高溫」,下午前後可以把分布的下半截直接砍掉,機率會比開盤時銳利很多。v2 可以在結算日每小時跑一次,用「已觀測最高溫 + 剩餘時段的 ensemble」重算機率。
- 注意:這也是很多人在做的事,edge 可能只剩幾分鐘到一兩小時,先用紙上交易確認有沒有。

### 5. 管線換掉 Google Sheet
- GitHub Actions 排程 + 資料 commit 成 CSV/Parquet(或 Cloudflare D1)。不需要 OAuth、不怕 token 過期、本機關機也照跑。
- 本機 cron 不再用。

## 範圍建議
- 先只追 **2~3 個市場最活躍的城市**,不要一次五城。
- 先只做**日最高溫**(Polymarket 天氣市場主力),低溫之後再說。
